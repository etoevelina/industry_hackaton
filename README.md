# Локальная система прокторинга — Integrity Score вместо надзора

Система отвечает не на вопрос «списывал или нет», а на вопрос **«насколько можно доверять
результату этого экзамена»** — и показывает, из чего это доверие сложилось. Защищённая
оболочка (Electron) держит рабочее окружение, Python-сайдкар смотрит в камеру и микрофон,
движок событий превращает шумные покадровые наблюдения в редкие обоснованные инциденты, а
fusion-слой связывает поведение студента с содержанием его ответов. На выходе — подписанный
HTML-отчёт с хеш-цепочкой: преподаватель получает факты за тридцать секунд вместо двух часов
просмотра записи, а решение по-прежнему принимает человек. Всё работает **полностью локально**:
ни один кадр, ни один сэмпл звука, ни один байт телеметрии не уходит в сеть.

## Быстрый старт — четыре команды

```bash
bash scripts/setup.sh      # .venv, зависимости сайдкара и оболочки, самопроверка
make models                # веса детектора объектов (однократно, единственный шаг с сетью)
make run                   # сайдкар + оболочка; Ctrl+C гасит оба процесса
make verify                # проверить подпись отчёта и хеш-цепочку доказательств
```

Нет камеры, моделей или времени — работает демо-режим по сценарию:

```bash
make run-mock              # мок-сайдкар гоняет scripts/demo_scenario.json, камера не нужна
make test                  # импорты, синтаксис JS, валидность сценария демо
```

Мок говорит по тому же протоколу и считает risk-score теми же весами — оболочка разницы
не видит. Это план Б на демо-день, см. [`docs/DEMO.md`](docs/DEMO.md).

Опциональные каналы ставятся отдельно и **не обязательны**:
`bash scripts/setup.sh --vision --audio --identity`. Отсутствие пакета выключает свой канал,
а не систему — см. [таблицу деградации](docs/ARCHITECTURE.md#4-деградация).

## Сверх ТЗ — семь вещей, которых в кейсе нет

| Что | Зачем это, какую дыру закрывает |
|---|---|
| **Fusion поведения и содержания** ([`engine/fusion.py`](sidecar/engine/fusion.py)) | Отвод взгляда сам по себе не доказывает ничего. Связка «взгляд ушёл на 5.2 с → через 1.1 с 312 символов со средним интервалом 11 мс при базовой скорости студента 170 мс» — доказывает. Закрывает главный вектор 2026 года: LLM на втором устройстве. |
| **Непрерывная верификация личности** ([`detectors/identity.py`](sidecar/detectors/identity.py)) | Обычный прокторинг проверяет лицо один раз на входе — дальше за клавиатуру может сесть кто угодно. Сверка эмбеддинга раз в 3 с, решение по скользящему окну. |
| **Анти-спуфинг (liveness)** | Фото перед камерой, зацикленное видео, подменённый поток: отсутствие морганий, статичность области лица, детект повтора последовательности кадров. Работает даже без insightface — на одном numpy. |
| **Проверки окружения** ([`env_checks.py`](sidecar/env_checks.py)) | Виртуальная камера (OBS/ManyCam/Droidcam/EpocCam), ПО удалённого доступа, виртуальная машина, запись экрана, чёрный список процессов, второй монитор. Это второй, независимый от камеры источник доказательств: подмену видеопотока в кадре не увидеть принципиально. |
| **Аудио-канал** ([`detectors/audio.py`](sidecar/detectors/audio.py)) | Главный признак — не распознавание голоса, а рассинхрон: речь в микрофоне есть, губы сомкнуты (`SPEECH_WITHOUT_LIP_MOTION`). Так выглядит подсказка через наушник. Звук на диск не пишется никогда. В шумном компьютерном классе канал даёт ложные срабатывания на соседей, поэтому выключается одним флагом (`make run ARGS="-- --no-audio"`) — см. [`LIMITATIONS.md`](docs/LIMITATIONS.md#3-ограничения-моделей-где-возможны-ошибки-и-что-с-ними-сделано). |
| **Подписанный tamper-evident отчёт** ([`storage/db.py`](sidecar/storage/db.py), [`storage/report.py`](sidecar/storage/report.py)) | `hash_n = sha256(prev_hash ‖ canonical_json(body_n))`, genesis выводится из метаданных сессии, отчёт подписан Ed25519. Правка одного байта рвёт цепочку, `make verify` показывает номер записи. Отчёт перестаёт быть картинкой и становится доказательством. |
| **Гуманная эскалация** ([`engine/risk.py`](sidecar/engine/risk.py)) | 30 баллов — мягкая подсказка в HUD, 60 — пауза, 90 — блокировка. Студент всегда видит, что именно зафиксировано; risk-score затухает (half-life 90 с), поэтому случайная ошибка на второй минуте не клеймит до конца теста; разложение по видам событий даёт преподавателю не «риск 64», а «телефон ×2 +41, взгляд вниз ×3 +18». Приговор система не выносит. |

## Приватность

Это система прокторинга, а не слежки. Что именно происходит с данными:

**Что пишется на диск**
- `sessions/<ts>_<student_id>/evidence.sqlite` — журнал инцидентов: вид, время, длительность,
  уверенность, числовые детали, русская формулировка. Каждая запись связана хешем с предыдущей.
- `sessions/<ts>_<student_id>/evidence/` — кадры и 15-секундные клипы **только вокруг
  подтверждённых инцидентов**. Кроп делается по боксу предмета-повода. Отдельные кропы лиц
  не сохраняются; для `SECOND_FACE` и `IDENTITY_MISMATCH` доказательством служит полный кадр,
  а лица посторонних на нём размываются. Для `SECOND_FACE` клип не пишется вовсе: размыть
  движущегося постороннего в видео нечем, и биометрия человека, который на экзамен не
  подписывался, на диск не попадает.
- `report.html` + `report.html.sig` + `report.html.pub` — отчёт, подпись, публичный ключ.

**Что не пишется никогда**
- Видео целиком. Кадры живут только в оперативном кольцевом буфере (несколько секунд) и
  затираются при закрытии.
- Звук. Ни wav, ни «временные файлы для отладки»: сэмплы существуют только в ОЗУ, наружу
  уходят лишь производные признаки (флаг речи, RMS, близость к профилю голоса).
  Распознавание слов не делается и не предусмотрено.
- Нажатые клавиши и текст ответов. Телеметрия для fusion — это межклавишный интервал в
  миллисекундах, класс клавиши (`char`/`nav`/`ctrl`) и длина вставки. Символы не покидают
  renderer. Кейлоггер в системе прокторинга невозможно защитить, и мы его не делали.
- Эталон лица и профиль голоса. Это векторы признаков, а не изображения и записи, и до
  диска они не доходят вообще: живут в памяти процесса сайдкара и исчезают вместе с ним.
  В каталоге сессии их нет, восстановить по ним исходные данные нельзя.

**Где это лежит и куда не уходит**
- Всё внутри репозитория: `sessions/`, `evidence/`, `keys/`. Эти каталоги в `.gitignore`.
- Сетевых обращений наружу нет ни одного. Единственный канал — WebSocket на `127.0.0.1:8787`
  между двумя локальными процессами. Единственный шаг, которому нужен интернет, —
  однократная подготовка весов `make models` до экзамена.
- Студент видит в HUD всё, что фиксируется: активные каналы, текущий risk-score, список
  инцидентов с формулировками. Скрытого режима нет.

Этика, минимизация данных и право студента — [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md#этика-и-приватность).

## Требования

Python 3.12 (минимум 3.10), Node 20, macOS arm64 — основная платформа разработки;
Windows-специфичный код изолирован и не влияет на импорт на macOS.
Обязательных зависимостей четыре: `websockets`, `numpy`, `opencv-python`, `psutil`.
Всё остальное — опционально.

### Проверенная конфигурация

Сборка прогнана end-to-end на macOS arm64 / Python 3.12.10 / Node 20 / Electron 33
**без единого тяжёлого ML-пакета**: `mediapipe`, `onnxruntime`, `ultralytics`,
`insightface`, `torch`, `librosa`, `sounddevice`, `webrtcvad` не установлены. Ставилось
только ядро и отчёт — ровно то, что даёт `bash scripts/setup.sh` без флагов:

```
websockets 15.0.1   numpy 1.26.4   opencv-python 4.11.0.86
psutil 7.2.2        jinja2 3.1.6   cryptography 46.0.7
```

В этой конфигурации каналы `vision`/`gaze`/`identity`/`audio` честно отдают
`available() == False` и уходят в `hello.degraded`, а работают: WebSocket-протокол
целиком, EventEngine, RiskScorer, FusionEngine, проверки окружения, SQLite с
hash-chain, сборка и подпись отчёта, оболочка Electron и весь демо-сценарий из
`scripts/demo_scenario.json`. Ни один отсутствующий пакет не роняет систему —
это и проверялось в первую очередь.

### Проверка отчёта

`scripts/verify_report.py` принимает и файл отчёта, и каталог сессии целиком
(каталог обычно и копируют на флешку):

```bash
python3 scripts/verify_report.py sessions/<сессия>/report.html
python3 scripts/verify_report.py sessions/<сессия>          # то же самое
make verify                                                 # последняя сессия
python3 scripts/verify_report.py <отчёт> --trusted-pub university.pub
```

Коды возврата: `0` — подпись и цепочка сошлись, `1` — обнаружена подделка,
`2` — проверить не удалось (нет файлов, нет `cryptography` либо публичный ключ
не сверен с эталоном).

Про эталон ключа. `report.html.pub` едет вместе с отчётом, поэтому сам по себе
он ничего не доказывает: кто пересоберёт отчёт и подпишет его своим ключом,
получит согласованную пару «отчёт + подпись». Поэтому проверка сверяет ключ с
эталоном — `keys/report_ed25519.key.pub` на машине экзамена или файл из
`--trusted-pub`. Эталон совпал — код `0` и «ОТЧЁТ ПОДЛИННЫЙ»; не совпал — код
`1`; эталона нет — код `2` и прямая формулировка, что подлинность ключа не
подтверждена. В продуктовой версии эталонный ключ хранится у вуза, а подписывает
отчёты сервис экзамена, а не машина студента (см. `docs/LIMITATIONS.md`, §4).
